# 抖音图文发布前快速路径

仅在用户要求通过 Computer Use 操作抖音创作者中心图文发布页时读取。该案例来自真实跑通的发布前测试，但不会授权点击“发布”。

## 完成定义

默认发布前状态包含：

- 8 张图片按文件顺序上传；
- 标题不超过 20 字；
- 正文完整且不超过 1000 字；
- 恰好 5 个从候选列表激活的平台有效话题；
- 可见性、保存权限和跨平台同步设置符合用户要求；
- 页面检测没有阻止发布的异常；
- 停在“发布”按钮之前。

音乐、位置、合集、热点和定时发布属于可选字段，只有用户或上游工作流要求时才纳入完成定义。

## 黄金路径边界

1. 在内容管理页读取一次状态，确认账号和入口。
2. 进入“发布图文”，读取一次完整编辑页状态。
3. 打开文件选择器，一次选择全部图片。
4. 返回网页并等待“已添加 8 张图片”。
5. 在空编辑器中一次写入标题和完整正文；先核对正文末句，再创建话题。
6. 用编译式内循环逐个激活 5 个话题。
7. 读取一次完整状态，核对图片、标题、正文、话题、设置、预览和页面检测。
8. 不点击“发布”；若用户随后要求发布，在动作发生前执行当前 Computer Use 确认要求。

## 文件选择器

中文深层路径在 macOS 文件选择器里不适合逐字输入。可在本地预先创建一个临时 ASCII 路径指向本条图片目录，然后在文件选择器中：

1. `super+shift+g` 打开“前往文件夹”；
2. 确认 Chrome 仍在前台；若其他应用抢焦点，先重新读取状态并聚焦 Chrome；
3. “前往文件夹”输入框可能保留旧路径，先全选或三击清空，再用 `type_text` 输入 ASCII 路径并确认；
4. `super+2` 切到列表视图；
5. 用点击第一行或一次 `Down` 明确选中第一张，两种方式只选一种；
6. 连续 7 次 `shift+Down` 选满剩余 7 张，确认“打开”按钮已启用；
7. 点击“打开”；
8. 回到网页后只以“已添加 8 张图片”为上传成功证据；若显示 7 张，立即补齐，不继续填写正文。

如果“前往文件夹”不可用，使用列表视图和可访问性“打开项目”动作逐层进入目录。不要因为路径输入失败而改名或移动源素材。

## 正文与话题

抖音正文是 Slate 富文本编辑器。稳定顺序是“完整正文一次写入 → 5 个话题逐个激活 → 最终核验”。

- 空编辑器用一次 `set_value` 写入完整正文。
- 非空编辑器先清空并重新读取，再写入正文；不要让旧 Slate 节点与新正文叠加。
- 创建结构化话题后，不再用 `select_text`、`End` 或坐标补正文。发现正文缺句时，重置编辑器并从正文开始重放。
- 直接粘贴 `#话题` 只是普通文本，不能作为完成证据。
- 正文与标题分别写入并分别核对，不在一次动作串里连续调用多个 `paste`。剪贴板读取超时时，先重新聚焦 Chrome 并恢复完整正文，不能继续创建话题。

已验证的候选激活内循环：

1. 点击 `#添加话题`，读取状态，确认编辑器获得新的 `#` 输入位；
2. 粘贴不带 `#` 的话题文本并读取候选状态；
3. `BackSpace` 删除最后一个字符，再用 `type_text` 重新输入最后一个字符，以触发精确候选；
4. 只有第一候选与目标完全一致时，才可用 `Down`、`Return` 选择；否则退出编译模式并人工读取候选文本；
5. 读取状态，从最新文本中解析下一次 `#添加话题` 索引；
6. 缺少入口、候选不一致或有效话题数不增长时立即停止。

平台话题芯片的可访问性文本可能省略末字，因此最终同时核对编辑器中的结构化话题数量和右侧预览，不只比较一个 AX 标签字符串。

页面巡检需要滚动时，先把焦点移出 Slate 编辑器。否则滚轮可能只滚动正文内部，造成“看似翻页、实际页面未动”的假进度。

若需要录屏，优先使用带固定时长的录制，让录制自然结束并落盘；中途强制终止可能得不到可用文件。录屏属于证据，不应进入公开仓库或包含账号隐私。

## 当前实测证据

一次发布前测试中，8 张图片、13/20 字标题、完整正文、5 个有效话题、公开、允许保存和不跨平台同步均在当前页面核验，页面显示“作品未见异常”，最终未点击发布。

其中 5 个有效话题的编译式内循环单次耗时为 14.743 秒，包含 15 次内部 `get_app_state`。这是单次路径观察，不是完整工作流基准，也不支持固定提速倍数。
