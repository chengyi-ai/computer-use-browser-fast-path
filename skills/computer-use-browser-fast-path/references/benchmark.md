# 可复现测速协议

用于验证提速效果或对外发布性能结论。测速比较的是 Agent 与浏览器交互开销，不是网站服务器性能。

## 选择任务

使用一个结果可验证、步骤足够重复、不会造成高风险后果的浏览器任务。推荐先用只读流程或测试账号，例如：

- 打开指定站点，搜索固定关键词并读取第一条结果；
- 在本地测试表单填写固定字段并到达确认页；
- 在测试队列中处理多条可撤销草稿。

不要用真实购买、永久删除、验证码或不可逆公开发布作为测速任务。

## 控制变量

基线和快速路径必须保持一致：

- 同一台机器、浏览器、账号和起始页面；
- 同一网络条件和浏览器窗口尺寸；
- 同一输入数据、任务完成定义与确认要求；
- 相同的冷启动或热启动条件；
- 网站没有已知故障或明显限流。

分别至少运行 3 次，报告中位数，不挑选最快单次结果。若任务会改变服务端状态，应使用隔离测试数据并在每次运行前恢复同一起点。

## 记录字段

每次运行记录：

| 字段 | 含义 |
|---|---|
| `elapsed_seconds` | 从首次浏览器状态读取到最终核验完成的总时间 |
| `state_reads` | `get_app_state` 调用次数 |
| `model_round_trips` | 模型与 Computer Use 工具之间的往返次数 |
| `full_state_reads` | 使用 `disableDiff: true` 的次数 |
| `screenshot_inspections` | 实际展开并读取截图的次数 |
| `ui_actions` | 点击、输入、快捷键、滚动等动作总数 |
| `blind_retries` | 未发现原因就重复同一动作的次数，目标为 0 |
| `correct` | 最终任务是否正确完成并得到 UI 证据 |
| `recovery_events` | 退出快速路径并恢复的次数 |
| `compiled_segments` | 在一次持久执行中完成的稳定动作段数量 |

只有 `correct=true` 的运行才进入速度比较。若快速路径更快但结果错误、重复提交或缺少核验，该结果无效。

## 计算

对两组有效运行分别取 `elapsed_seconds` 中位数：

```text
speedup = baseline_median / fast_path_median
time_saved = baseline_median - fast_path_median
```

公开表述应同时给出任务、运行次数、中位数和正确率。例如：

```text
在同一测试表单任务的 3 次有效运行中，基线中位数为 A 秒，快速路径中位数为 B 秒；两组正确率均为 100%。
```

没有这组数据时，只描述机制，例如“减少状态读取轮次”，不要写“快 3 倍”或“行业最快”。

编译式重放可能在保留相同 `state_reads` 的情况下显著减少 `model_round_trips`。公开报告时应同时给出两项，避免把“模型少看了几次工具输出”误写成“页面不需要核验”。

## 单次实测记录的表述

单次运行只能证明路径可执行，不能证明稳定提速。可以按以下格式记录观察值：

```text
在一次已跑通的抖音图文发布前测试中，5 个结构化话题的编译式重放耗时为 14.743 秒，包含 15 次内部状态读取；最终停在发布按钮之前。本记录是单次观察，不计算提速倍数。
```

若要对外宣称完整工作流提速，应从相同起始页面到相同发布前核验点运行至少 3 次，并另设同条件基线。
